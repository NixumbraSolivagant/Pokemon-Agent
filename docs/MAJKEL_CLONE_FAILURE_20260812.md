# Majkel 行为克隆失败复盘（2026-08-12）

本文记录 `majkel_fused_319_gpu0_v6` 的数据、训练结果、已证实失败原因和修复前置条件。结论以服务器上的冻结清单、训练缓存、artifact、教师强制审计和 64 局强度审计为准。

## 结论

本次模型确实完成了训练，也确实使用了 Majkel 新提交的数据。结果差的首要原因不是 GPU、下载或训练进程故障，而是停止头的训练权重被重复平衡，并与不可恢复的硬路由组合，系统性地诱导模型过早攻击或结束回合。

在修复训练目标、运行路由和评估一致性之前，不得直接使用完整 363 局重复当前方案，也不得降低门控阈值以接纳模型。

## 已证实的首要根因

### 停止头权重被重复平衡

MAIN 类型数据先通过 `balance_type_decisions()` 做动作类型平衡。`main_stop` 随后从已经平衡的类型数据生成，又通过 `balance_stage_decisions()` 做继续/终止阶段平衡。

直接从本次训练缓存重建得到：

| 阶段 | 真实终止样本比例 | 终止加权质量 |
| --- | ---: | ---: |
| 原始停止数据 | 15.36% | 15.36% |
| 类型平衡后 | 15.36% | 23.52% |
| 再做阶段平衡后 | 15.36% | 47.98% |

最终平均样本权重为：

- 继续动作：`2.1374`
- 攻击或结束：`10.8672`

因此一条终止样本对停止头的平均影响约为继续样本的 `5.1` 倍。测试集继续召回率只有 `77.46%`；按混淆矩阵估算，约有 307 次本应继续执行 PLAY、ATTACH、EVOLVE、ABILITY 或 RETREAT 的决策被提前路由到 ATTACK/END。

这属于训练目标错误，而不是简单的类别不平衡。增加回放数量不能自动修复该偏差。

### 硬路由使错误不可恢复

v6 runtime 使用硬 `stop -> type -> option` 路由：

1. `main_stop` 判断继续或终止；
2. `main_continue_type` 或 `main_terminal_type` 选择唯一动作类型；
3. 所有其他合法类型被赋值为 `-inf`；
4. 只有被选类型的 option head 参与最终选择。

类型内部子模型在正确路由条件下表现较强：

| Head | 验证 Top-1 |
| --- | ---: |
| `main_play` | 69.74% |
| `main_attach` | 77.33% |
| `main_evolve` | 94.07% |
| `main_ability` | 98.26% |
| `main_attack` | 94.04% |

但完整硬路由 MAIN 测试 Top-1 只有 `49.23%`。停止头或类型头一旦出错，正确动作会被直接删除，强子模型没有纠错机会。

### 停止判定没有校准保护

当前逻辑仅比较最高终止分数与最高继续分数。只要终止分数略高，就进入终止阶段，没有额外 margin、概率校准或低置信度回退。

由于停止头已经使用失真的类别权重，其分数不能直接解释为真实终止概率。把这种分数用于无阈值硬切换，会进一步放大提前攻击和提前结束问题。

## 评估体系缺陷

### `runtime_policy_metrics` 没有评估实际 v6 runtime

`evaluate_runtime_policy()` 仍调用旧的层级 MAIN 评估，而不是实际 v6 使用的硬路由评估。因此 artifact 中名为 runtime 的指标并不完全对应打包后的运行行为。

本次测试中：

- 层级 MAIN Top-3：`80.07%`
- 实际硬路由 MAIN Top-3：`75.26%`

错误评估会让训练选择和门控高估线上策略质量。

### 教师强制审计掩盖闭环漂移

当前行为审计在模型预测后恢复 memory，并写入 Majkel 的真实动作。下一步预测仍处于教师产生的状态和动作历史中。

因此它只衡量单步模仿，无法衡量模型自主执行后的状态漂移。第一次错误会改变手牌、场面、能量位置、已用能力、合法动作和策略 memory，之后模型会进入训练数据未覆盖的状态，错误持续累积。

### 终止指标定义需要统一

实际停止路由将 ATTACK 和 END 定义为终止。质量门控和历史审计曾把 RETREAT 和 END 汇总为 terminal，导致诊断指标与 runtime 语义不一致。

后续必须统一以 ATTACK + END 计算停止指标，并将 RETREAT 单独报告。

## 次要限制

### 高维稀疏泛化

- option 特征为 1,084 维，type 特征为 1,104 维。
- 训练 MAIN 决策约 7,100 条。
- 对全部 10,316 条 MAIN 决策进行精确特征签名后，没有发现完全相同的重复状态。

`main_type` 验证 Top-1 为 `61.89%`，但 Top-3 为 `97.80%`。这说明模型通常能把正确类型排入前列，却不足以支持无条件硬取第一名并删除其他类型。

### 胜负轨迹等权

普通策略 head 使用 `win_weight=1.0`、`loss_weight=1.0`，因此胜局和败局动作完全等权。失败局中仍包含大量合理动作，但输局后期的被迫选择或低价值分支会限制“最强策略”学习上限。

这不是本轮退化的首要原因。即使只训练胜局，停止头重复平衡和硬路由仍会存在。

### 旧数据与缺失数据不是主要原因

旧 80 局与新 239 局来自同一牌组，终止先验分别约为 `16.45%` 和 `16.29%`，整体阶段分布接近。旧数据可能存在细粒度策略漂移，但没有证据表明它造成当前大幅退化。

最后 44 局没有进入训练是事实，但补齐约 14% 数据无法修复错误的训练目标和路由结构。

## 修复前置条件

下一轮训练必须先完成以下修改：

1. 从未经过类型平衡的原始 MAIN 数据构建 `main_stop`，禁止继承类型权重后再次做阶段平衡。
2. 停止头默认保留真实阶段先验；如需代价敏感训练，只允许使用显式、可审计且不重复叠加的温和权重。
3. 为停止决策增加在验证集上校准的 margin 或阈值，并在置信度不足时保留继续动作竞争资格。
4. 用软路由或置信度回退替代无条件 `-inf`；至少允许全局 option 分数在上游路由低置信度时纠错。
5. 让离线 runtime 评估调用与打包 runtime 相同的路由实现，避免维护两套决策逻辑。
6. 统一终止定义为 ATTACK + END，RETREAT 单独统计。
7. 增加自主闭环审计，不再只依赖教师强制单步指标。
8. 在相同切分、种子和评测基线下，对比新 283 局纯模型与 `283 + 80` 降权融合模型。

## 重新训练与晋升标准

修复后按以下顺序验证，任何阶段失败都不得进入下一阶段：

1. 单元测试证明停止头没有重复权重，训练加权质量与配置一致。
2. 离线评估证明 artifact 指标与打包 runtime 对同一批决策产生一致结果。
3. 教师强制审计用于诊断 option head，闭环审计用于判断自主策略漂移。
4. 运行小规模 paired smoke，确认不再出现明显提前攻击或提前结束。
5. 运行固定种子 64 局强度评估；通过后再扩展到 256 局。
6. 保持现有严格质量门控和强度门控，不得为了填充对手池而降低阈值。

只有完成上述修复并通过门控，模型才可以进入对手池或成为最终提交候选。
